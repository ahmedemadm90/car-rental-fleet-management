# منصة رحلتي لتأجير السيارات وإدارة الأساطيل

منصة تطبيقات جوال وواجهة برمجية لإدارة سوق تأجير السيارات للأفراد، وحجوزات السفر وحفلات الزفاف، وعمليات الأسطول لدى مكاتب التأجير. يتكون المستودع من تطبيق **Laravel 13 API** وتطبيق **Flutter** بواجهة عربية من اليمين إلى اليسار.

> هذا المستودع هو **MVP تشغيلي** للميزات المدرجة أدناه، وليس نظام دفع أو تأمين قانوني جاهزاً للإنتاج. بوابات الدفع الحقيقية، رسائل SMS/WhatsApp، وتكاملات GPS والتأمين تحتاج حسابات مزودين ومفاتيح سرية وسياسات تشغيل قبل تفعيلها في أي بيئة إنتاج.

## هيكل المستودع

| المسار | التقنية | المسؤولية |
|---|---|---|
| `backend-laravel/` | Laravel 13 + Sanctum + SQLite افتراضياً | واجهة API، المصادقة، الحجوزات، وإدارة الأسطول |
| `frontend-flutter/` | Flutter | تطبيق الجوال العربي للعملاء وأصحاب مكاتب التأجير |

## الميزات المنفذة

### للعميل

يستطيع العميل إنشاء حساب أو تسجيل الدخول، والبحث عن السيارات المتاحة بحسب المدينة، واستعراض تفاصيل السيارة والمكتب، ثم إرسال طلب حجز يومي أو سفر أو حفل زفاف. يحتسب الخادم قيمة الحجز من السعر اليومي أو سعر الزفاف بحسب نوع الطلب ويمنع الحجز المتداخل على السيارة. يستطيع العميل كذلك مراجعة قائمة حجوزاته.

### لصاحب مكتب التأجير

يستطيع صاحب المكتب إنشاء مكتب تأجير، وإضافة سياراته مع بيانات اللوحة والتسعير وحالة التشغيل والعداد وخطة تغيير الزيت. تتضمن لوحة المتابعة إيراد الشهر والمصروفات وصافي الربح وحالة الأسطول والحجوزات المعلقة وتنبيهات الصيانة. ويسمح التطبيق بتسجيل مصروف أو صيانة لكل سيارة مع تحديث العداد وسجل الاستحقاق التالي للزيت أو الفحص.

### في الخلفية

توفر واجهة API مصادقة برموز Sanctum، وعزل بيانات كل صاحب مكتب عن المكاتب الأخرى، والتحقق من البيانات، وحالات الحجز، وعلاقات قاعدة البيانات بين المستخدمين والمكاتب والسيارات والحجوزات والمدفوعات والمصروفات وسجلات الصيانة. توجد أيضاً اختبارات تكامل لمسار بحث وحجز السيارة ومنع تضارب الحجوزات.

## تشغيل الخلفية محلياً

المتطلبات هي PHP 8.3 أو أحدث وComposer. يستخدم Laravel قاعدة SQLite افتراضياً، لذلك لا تحتاج إلى إعداد MySQL للتجربة الأولى.

```bash
cd backend-laravel
composer install
cp .env.example .env
php artisan key:generate
mkdir -p database
touch database/database.sqlite
php artisan migrate
php artisan serve
```

سيعمل الخادم محلياً على `http://127.0.0.1:8000` وتبدأ واجهات التطبيق من `http://127.0.0.1:8000/api/v1`.

## تشغيل تطبيق Flutter

المتطلبات هي Flutter SDK 3.10 أو أحدث وجهاز محاكي أو جهاز حقيقي. عنوان الواجهة البرمجية الافتراضي مخصص لمحاكي Android (`10.0.2.2`). عند استعمال جهاز فعلي أو iOS أو سطح المكتب، مرّر عنوان خادمك القابل للوصول إليه.

```bash
cd frontend-flutter
flutter pub get
flutter run --dart-define=API_BASE_URL=http://10.0.2.2:8000/api/v1
```

مثال لجهاز فعلي متصل بالشبكة المحلية:

```bash
flutter run --dart-define=API_BASE_URL=http://192.168.1.50:8000/api/v1
```

cd backend-laravel

## ملخص أهم مسارات API

| المسار | الطريقة | الغرض |
|---|---:|---|
| `/api/v1/auth/register` | `POST` | إنشاء حساب عميل أو صاحب مكتب |
| `/api/v1/auth/login` | `POST` | تسجيل الدخول وإصدار الرمز |
| `/api/v1/cars` | `GET` | البحث العام عن السيارات المتاحة |
| `/api/v1/bookings` | `POST` | إنشاء طلب حجز للعميل |
| `/api/v1/bookings/me` | `GET` | حجوزات العميل الحالي |
| `/api/v1/owner/dashboard` | `GET` | لوحة متابعة المكتب |
| `/api/v1/owner/shops` | `GET`, `POST` | عرض أو إنشاء مكاتب التأجير |
| `/api/v1/owner/shops/{shop}/cars` | `GET`, `POST` | عرض أو إضافة سيارات مكتب معين |
| `/api/v1/owner/cars/{car}/expenses` | `GET`, `POST` | المصروفات الدورية للسيارة |
| `/api/v1/owner/cars/{car}/maintenance` | `GET`, `POST` | سجل الصيانة والاستحقاقات |

## ما يحتاج قراراً أو بيانات خارجية قبل الإنتاج

تظل هذه عناصر تكامل إنتاجي وليست أخطاء أو ملفات مفقودة: بوابة تحصيل إلكتروني، ربط تأمين المركبات، التحقق من الهوية ورخصة القيادة، العقود والتوقيع الإلكتروني، إرسال الإشعارات، خرائط ومواقع التسليم، وأجهزة GPS. يفضّل تحديد الدولة القانونية ومزودي هذه الخدمات قبل إضافتها، لأن المتطلبات والبيانات الحساسة تختلف حسب السوق.

## الإشعارات الذكية والصيانة والتأمين

أضيف النظام سجلاً دائماً للإشعارات داخل الحساب، ورموز أجهزة المستخدمين، وأمراً مجدولاً يفحص يومياً استحقاق تغيير الزيت والفحص الدوري وانتهاء التأمين. يرسل النظام إشعاراً إلى مالك مكتب التأجير ويمنع تكرار التنبيه نفسه في اليوم ذاته.

```bash
cd backend-laravel
php artisan notifications:send-vehicle-reminders
php artisan schedule:work
```

في الإنتاج، يجب تشغيل مجدول Laravel كل دقيقة أو تشغيل `schedule:work` كخدمة مستمرة. أمر الفحص نفسه يعمل كل يوم الساعة 09:00 وفق المنطقة الزمنية للخادم.

### تفعيل Push عبر Firebase

التطبيق يحتوي على تكامل Firebase Messaging، لكنه **معطل افتراضياً** حتى لا يفشل البناء من دون مشروع Firebase. لإرساله فعلياً، أنشئ مشروع Firebase ثم شغّل `flutterfire configure` من مجلد Flutter لإضافة إعدادات Android/iOS/Web الخاصة بمشروعك. بعد ذلك ضع مسار حساب خدمة Firebase على الخادم في `FIREBASE_CREDENTIALS`، وفعّل `FCM_ENABLED=true`، ثم شغّل التطبيق هكذا:

```bash
flutter run --dart-define=FIREBASE_ENABLED=true --dart-define=API_BASE_URL=https://your-api.example/api/v1
```

ينبغي تفعيل Push Notifications وBackground Modes ورفع مفتاح APNs إلى Firebase عند إصدار iOS. لا ترفع ملفات Firebase أو حساب الخدمة إلى GitHub.

## الدفع الإلكتروني عبر Paymob Hosted Checkout

يُنشئ التطبيق جلسة دفع للحجز، ثم يعرض صفحة Paymob المستضافة داخل التطبيق. لا تمر بيانات البطاقات عبر تطبيق Flutter أو خادم Laravel. لا تُعتبر نتيجة صفحة العودة وحدها تأكيداً للدفع؛ الـ Webhook الموقّع بـ HMAC هو المصدر الوحيد لتغيير حالة الدفع والحجز إلى مؤكد.

أضف القيم الآتية إلى `backend-laravel/.env` بعد إنشاء حساب Paymob اختباري أو إنتاجي:

```dotenv
PAYMOB_SECRET_KEY=
PAYMOB_PUBLIC_KEY=
PAYMOB_INTEGRATION_ID=
PAYMOB_HMAC_SECRET=
PAYMOB_CURRENCY=EGP
APP_URL=https://your-api.example
```

بعد نشر الخادم بعنوان HTTPS عام، سجّل رابط Webhook التالي في إعدادات Paymob:

```text
https://your-api.example/api/v1/payments/paymob/webhook
```

اختبر أولاً ببيانات Sandbox، ثم نفّذ دورة كاملة: إنشاء الحجز، فتح Checkout، دفع تجريبي، Webhook موثق، تأكيد حالة الحجز، ثم اختبار الفشل أو الإلغاء. مفاتيح Paymob السرية وHMAC ومفتاح Firebase يجب أن تبقى على الخادم فقط ولا توضع أبداً في Flutter أو GitHub.
